# 算法说明（ALGORITHMS）

## 1. L1 规则启发式（RuleScheduler）

构造式列表调度：每一步从"当前可派的下一道工序"里按规则打分选一个，
交给共享解码器放置。同一订单内严格按工艺链推进。

| 规则 | 打分依据 | 适用 |
|---|---|---|
| EDD | 交期最早优先（同交期急单优先） | 交付导向，默认 |
| SPT | 单件工时最短优先 | 减少在制、快速出货 |
| WSPT | 优先级权重 / 工时 最大的优先 | 高价值订单优先 |
| PRIORITY | 优先级数字优先，同级比交期 | 急单插队场景 |
| FIFO | 下达最早优先 | 公平、简单 |
| CR | 临界比 (交期-下达)/剩余工时 最小优先 | 交期紧张度 |

`rule=AUTO` 时六条规则全跑（共享解码器，均为毫秒级），取目标函数最优的一个。
`AUTO` 同时是 GA 的种子来源，所以**前端看到的"规则基准"和 GA 的起点是同一个解**。

## 2. L2 遗传算法（GaScheduler）

### 2.1 编码：OS + MS 双段（FJSP 标准编码）

```
个体 = { os: [订单号序列], ms: [每道工序的可选设备下标] }
```

- **OS 段**：订单号第 k 次出现 = 该订单第 k 道工序。只表达"订单间的先后"，订单内的
  工艺顺序由解码器保证——所以任意 OS 排列都不会产生非法解；
- **MS 段**：`ms[op] = 该工序选第几个可选设备`。与 OS 解耦，交叉变异互不干扰。

### 2.2 种子策略（本项目 GA 不退化的关键）

GA 种群第 0 号个体不是随机解，而是 **L1 AUTO 规则解原样反编码**：

1. 设备选择：规则解每道工序实际选中的设备 → `ms`；
2. 派工顺序：解码器落盘的 `Solution::opOrder`（真实放置顺序）→ 展开 `os`。

> 这里有一个实测过的坑：如果按"开工时间排序"去反推 OS，在同时刻并列时会打乱顺序，
> 插入式解码对顺序敏感，1200 工序下重建出的目标值比原解差 50%——GA 就永远追不上
> 规则基准。所以 `Solution` 专门存了 `opOrder` 字段。

种子构造时间计入总预算（超大算例退化为只用 EDD 种子），保证对外承诺的时限是真的。

### 2.3 遗传算子

| 算子 | 做法 | 说明 |
|---|---|---|
| 选择 | 锦标赛（k=3） | 无需全局排序 |
| OS 交叉 | POX（优先保留顺序交叉） | 随机选订单集合，子代1保留父1的这些订单相对顺序，其余位置补父2 |
| MS 交叉 | 均匀交叉 | 每道工序 50/50 取父 |
| OS 变异 | 交换 + 插入位移 | 两种模式随机 |
| MS 变异 | 随机重选 2 道工序的设备 | 扩大柔性搜索 |

### 2.4 多岛并行 + 局部搜索

- 岛数 = `min(4, 硬件线程数)`，每岛独立种群独立演化（多种子并行，天然并行化）；
- 岛 0 注入规则解种子，岛 1 注入 WSPT 规则解，其余随机初始化；
- 停滞 1/3 上限后变异率 ×1.05 爬升（上限 0.6），跳出局部最优；
- 总预算的 40% 留给**关键工序局部搜索**：
  1) 逐道关键工序试换设备（MS 维度直接下降）；
  2) 随机把工序在 OS 里前移（缩短关键路径）；
  只接受改进的爬山，不做退火——时间预算有限，简单有效。
- 各岛在代与代之间检查 deadline，初始化阶段也检查（大算例的种群初始化本身就要几十次解码），
  **不会超出用户设定的时间预算**。

### 2.5 评价一致性

GA 的适应度 = 共享解码器的目标值，与规则法、前端 KPI **同一套代码算出来**；
最终结果再由独立校验器复核（V1~V6），`feasible=false` 的解不会进入仓储。

## 3. 目标函数与 KPI

```
objective = w_t · Σ(延期小时 × 优先级权重 × 急单1.5)
          + w_s · 换型总分钟
          + w_m · makespan 小时
```

| KPI | 计算 |
|---|---|
| OTD | 完工 ≤ 交期的订单 / 总订单 |
| totalTardiness / maxTardiness | Σ max(0, 完工-交期) / 最大值 |
| makespan | 首工序占用起点 → 末工序结束（时钟跨度） |
| 换型次数/时长 | 相邻工序换型族变化计数（同族也可能有小换型，如检测对版 5 分钟） |
| 利用率 | 纯加工秒 / 日历可用秒（分母不含休息时段，分子不含换型） |
| 峰值 WIP | 任意时刻"已开工未完工"工序数峰值 |

## 4. 重排算法（Rescheduler）

### 4.1 急单插入

1. 急单按工艺链展开，优先级 5、urgent 标记；
2. 逐道工序调用共享解码器插入（只允许排在未冻结时段之后）；
3. 若与既有未冻结工序冲突，做**局部顺延 + 连锁修复**（`relayoutFrom` 同解码器自愈）；
4. 报告 `movedOps / machineChanges / totalShiftHours / stabilityCost`。

### 4.2 设备故障

1. 目标设备日历从 `now` 起**整段置空**（不删工艺路线，已开工工序依然合法——
   早期版本直接从 routing 里剔除设备，导致已开工工序违反 V2 校验，已废弃）；
2. 该设备上未开工的工序按原派工顺序重放（`Solution::opOrder`），在候选组内选最早可完工设备；
3. 每次迁移后对受影响机器段做 `relayoutFrom` 连锁顺延，迭代至无违规；
4. 稳定性代价 = 时间偏移总和 + 换机惩罚。

### 4.3 冻结语义

`frozen=true` 的工序在任何重排中时间与设备都不动；重排只处理
"未冻结 ∩ 受事件影响" 的工序集合——这是"计划漂移可控"的结构性保证。
